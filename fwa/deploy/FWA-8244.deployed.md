Each runtime is one STOP byte followed by its slice of the page. Deployed by
plain `CREATE` from `0x68575B073DE49a94e3E3ACf6F3A0d6E3b66267C7`, the wrapper
immediately after them at nonce 796. Chunks 1–8 cost 5,368,866 gas each,
chunk 9 3,877,281, the wrapper 1,486,749 — 47.3M gas in total, which at the
0.06–0.12 gwei base fee of those thirty blocks came to about **0.0047 ETH**.

The chunk contracts hold no source and are not verified on Etherscan; there is
nothing to verify, and `scripts/verify.mjs` checks something stronger — that
each one's runtime code is byte-identical to what the chunker builds from the
repo page.

## The constructor is the check

`Fwa8244` takes the chunk list and a keccak commitment to the page, reassembles
the document during construction, and reverts unless it hashes to the
commitment. A missing chunk, a reordered list, or a chunk from a different build
therefore cannot produce a deployed contract at all — the gas estimate for the
wrapper succeeding was already proof that the nine deployed chunks add up to
this exact page, before the transaction was ever broadcast.

## What was checked after deploy

- every chunk's runtime code is byte-identical to its build artifact
- the nine concatenated reassemble to `dapp/page.html` exactly
- `html()` returns 214,280 bytes identical to the repo page
- `request()` answers `200` with `text/html` and
  `public, max-age=31536000, immutable`
- `resolveMode()` is `"5219"`; `generation()` is 1; `latest()` is itself
- `PREVIOUS` and `successor` are both zero
- `steward()` is `0x1C0Aa8cCD568d90d61659F060D1bFb1e6f855A20`
- `PAGE_HASH`, `PAGE_LENGTH` and `chunkCount()` are the page's own
- `NAME` / `VERSION` are `fwa.wei` / `0.1`
- the w4eth.io gateway serves the identical 214,280-byte document
- the source is verified on Etherscan against solc 0.8.30, optimizer 200
- `fwa.wei` resolves on chain to this contract, and `https://fwa.wei.limo/`
  serves the identical document

`node scripts/verify.mjs fwa` reports `verified` against mainnet.

## The name

`fwa.wei` resolves on chain to this contract, and `https://fwa.wei.limo/` serves
the identical 214,280-byte document.

The name points at the **version contract directly**, as `poidh.wei` does, not
at a resolver. A successor deployed through `deployNext` therefore does not move
the name with it: the name is repointed by hand, or pointed at a resolver later
if the release model wants the delay poidhverse has.

## Growing it

Nine chunks hold 221,184 B and the page is 214,280 B, so there are **6,904 B**
of headroom. Past that the count — and therefore the address — has to change,
which means a successor deployed through `deployNext`, not an edit.
